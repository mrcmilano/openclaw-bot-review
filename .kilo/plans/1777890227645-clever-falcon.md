# Security Update Plan: Dependencies & Authentication

## Overview

This plan addresses two critical security concerns identified in SEC_REVIEW.md and LOCALUSE_SEC_REVIEW.md:
1. **Dependency vulnerabilities** - Next.js 16.0.0, React 19.0.0, and React-DOM 19.0.0 contain multiple CVEs including RCE (CVE-2025-66478, CVSS 10.0)
2. **No authentication** - All 25 API routes expose sensitive bot configs, credentials, and session data without any access control

## Phase 1: Update Security-Critical Dependencies

### 1.1 Update package.json dependencies

Update the following in `package.json`:

| Package | Current | Target | Reason |
|---------|---------|--------|--------|
| `next` | `^16.0.0` | `^16.2.3` | Patches CVE-2025-66478 (RCE), CVE-2025-55184 (DoS), CVE-2026-23869 (DoS), CVE-2026-29057 (smuggling), CVE-2026-23864 (DoS), CVE-2025-55183 (info leak) |
| `react` | `^19.0.0` | `^19.1.0` | Patches React Server Components vulnerabilities |
| `react-dom` | `^19.0.0` | `^19.1.0` | Patches React Server Components vulnerabilities |

### 1.2 Run npm install and verify

- Run `npm install` to update lock file
- Run `npm run build` to verify the app still builds correctly
- Run `npm run dev` to verify the app starts without errors

## Phase 2: Add Basic Authentication Mechanism

### 2.1 Create authentication middleware

**File: `middleware.ts`** (new file at project root)

- Create Next.js middleware that intercepts all requests
- Check for `Authorization: Basic` header
- Validate credentials against environment variables `AUTH_USERNAME` and `AUTH_PASSWORD`
- Return 401 with `WWW-Authenticate` header if credentials missing/invalid
- Allow unauthenticated access to `public/` static files only
- Support disabling auth entirely when `AUTH_DISABLED=true` (for local-only use)

### 2.2 Create environment variable template

**File: `.env.example`** (new file)

```
AUTH_USERNAME=admin
AUTH_PASSWORD=change-me-to-a-secure-password
# AUTH_DISABLED=true  # Uncomment to disable auth (local-only use)
```

### 2.3 Update Dockerfile for auth support

**File: `Dockerfile`**

- Add support for passing `AUTH_USERNAME` and `AUTH_PASSWORD` as runtime environment variables
- No changes needed to build stage, just document the env vars

### 2.4 Update documentation

**File: `README.md`**

- Add section explaining how to configure authentication
- Document the environment variables
- Explain the `AUTH_DISABLED` option for local-only use

## Implementation Details

### Middleware Logic

```typescript
// middleware.ts
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function middleware(request: NextRequest) {
  // Skip auth if disabled
  if (process.env.AUTH_DISABLED === 'true') {
    return NextResponse.next();
  }

  // Skip auth for static public files
  if (request.nextUrl.pathname.startsWith('/_next/') || 
      request.nextUrl.pathname.startsWith('/favicon') ||
      request.nextUrl.pathname.match(/\.(png|jpg|svg|ico)$/)) {
    return NextResponse.next();
  }

  const authHeader = request.headers.get('authorization');
  
  if (!authHeader) {
    return new NextResponse('Authentication required', {
      status: 401,
      headers: { 'WWW-Authenticate': 'Basic realm="OpenClaw Bot Dashboard"' },
    });
  }

  const expected = Buffer.from(
    `${process.env.AUTH_USERNAME}:${process.env.AUTH_PASSWORD}`
  ).toString('base64');

  if (authHeader !== `Basic ${expected}`) {
    return new NextResponse('Invalid credentials', {
      status: 401,
      headers: { 'WWW-Authenticate': 'Basic realm="OpenClaw Bot Dashboard"' },
    });
  }

  return NextResponse.next();
}

export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico).*)'],
};
```

### Environment Variables

- `AUTH_USERNAME` - Username for basic auth (required unless AUTH_DISABLED)
- `AUTH_PASSWORD` - Password for basic auth (required unless AUTH_DISABLED)
- `AUTH_DISABLED` - Set to `true` to disable authentication (for local-only use behind IAP)

## Risk Assessment

- **Dependency updates**: Low risk - Next.js 16.2.x and React 19.1.x are backward compatible with 16.0.0/19.0.0
- **Basic auth**: Low risk - Simple implementation, can be disabled for local use, adds defense-in-depth even when behind IAP

## Testing Plan

1. After dependency updates: `npm run build` and `npm run dev` to verify app works
2. After auth implementation:
   - Test with `AUTH_DISABLED=true` - should work without auth
   - Test without credentials - should get 401
   - Test with wrong credentials - should get 401
   - Test with correct credentials - should access normally
   - Test API routes specifically to ensure they're protected
